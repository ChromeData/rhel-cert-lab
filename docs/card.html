REFERENCE CARD

How to read any question

1. Find the trigger word. It tells you which sequence. 2. Run that sequence. Same steps every time. 3. Circle the values. Everything else in the question is fill-in-the-blank.

Trigger word → sequence

If the question says…Use
volume, VG, LV, extents, swap, partition, filesystem, mountSTORAGE
web server, FTP, NFS, "still running after reboot", "reachable from"SERVICE
user, group, shell, UID, password, agingUSERS
IP address, hostname, gateway, DNS, IPv6NETWORK
SELinux, context, enforcing, boolean, port label, 403SELINUX
every day, at HH:MM, schedule, cron, timerSCHEDULE
don't know the root password, can't log inRECOVERY
repository, yum source, dnf source, install fromREPO
kernel, default boot, boot parameterKERNEL
owner, permissions, read/write, ACL, only members ofPERMISSIONS

The 10 sequences

STORAGE make it → format it → mount it → fstab it → mount -a

SERVICE install → enable --now → firewall --permanent → --reload

USERS group first → users → passwords

NETWORK nmcli con mod → nmcli con up → hostnamectl

SELINUX edit /etc/selinux/config → setenforce → restorecon (or semanage for ports)

SCHEDULE enable the scheduler → write the job

RECOVERY interrupt GRUB → get a shell → passwd → autorelabel → reboot

REPO write the .repo file → dnf repolist

KERNEL install (never update) → grubby → reboot

PERMISSIONS chown → chmod → setfacl if named users are involved

Then circle the values

Everything the question gives you is a blank to fill:

Create volume group vgapp with a 8M physical extent size, logical volume

lvdata of 1G, formatted xfs, mounted persistently at /srv/app

Sequence: STORAGE. Blanks: name, extent size, name, size, filesystem, path. Nothing left to invent.

Two phrases that change the answer

"persistently" / "after reboot" / "at boot" → it must be in a config file, not just running. This is where the points are.

"add" / "without disturbing" / "do not remove" → you are adding to something, not replacing it. There is usually a + or an append involved.

Every task ends the same way


mount -a          (if you touched fstab — silence means safe)

verify it → reboot → verify it again

If it passes before the reboot and fails after, it was never really done.

Where the flags come from

Not memory. man <command>, or man -k <topic> when you don't know the command's name.

You memorize the sequence. You look up the flags. The question supplies the values.
